継承とポリモフィズム
既存のクラスをもとに新しいクラスを定義することができる。これを継承という。
元なるクラスをスーパークラスといい、新たに定義されているクラスをサブクラスという

構文
[修飾子] class サブクラス名 extends スーパークラス名{}
class Employee{}
class Sales extends Employee{}

スーパークラスの中にある変数やメソッドはサブクラスに引き継がれる。
スーパークラスはサブクラスに一つしか継承できない。


オーバーライド
スーパークラスのメソッドと同じ名前でメソッドを定義することができる。
サブクラスがインスタンス化され。オーバーライドされたメソッドが呼び出された場合は、オーバーライドされたものが優先的に呼び出される。

ルールとして
メソッド名、引数名が同じであること、戻り値はスーパークラスで定義したメソッドが返す型と同じか、そのサブクラス型でないといけない。
また、アクセス修飾子はスーパークラスと同じか、それよりも範囲が広いものでないといけない。
サブクラスのみ処理を変更したいときに有効。　　


thisとsuperの利用
thisは自分自身のオブジェクトを表現する
int id;インスタンス変数
void setId (int id){ローカル変数
id=id;
}
このようになっているときにローカル変数とインスタンス変数の名前が同じ場合、インスタンス変数への代入は行われない。
だからthisを付ける


抽象クラス
今まで定義してきた具体的な処理が行えるメソッドを具象クラスという。
一方で処理内容を記述しないものを抽象クラスという。
構文
[アクセス修飾子] abstract class クラス名｛｝
クラス宣言時にabstract修飾子を宣言する。そして、newによるインスタンス化はできないため、これを継承しているサブクラスを用いてインスタンス化する。
抽象クラスを継承したサブクラスが具象クラスの場合、抽象クラスのメソッドをすべてオーバーライドしないといけない。
そうでない場合は任意になる

構文
[アクセス修飾子] abstract 戻り値　メソッド名(引数リスト)
抽象メソッドのため処理は書けない。

インターフェース
実装クラスにルールを定義することができる。

ポリモフィズム
これはどういう意味か、共通のインターフェースを持つ処理でも実際にはオブジェクトごとに違うふるまいや動作をするということ。

コレクション
複数のオブジェクトを扱うときには配列を使用していました。しかしこれは、後から配列が大きくなったり、減らしたりすることができない。
そのためコレクションインターフェースを使用する。

List
配列で取得でき、
重複を許容し順序付けを行いたい場合はListインターフェースの利用をする。
Listインターフェースの中にArrayListというクラスがある。
ArrayListに<>このように定義し、そこに参照型の型定義を行う。

Set
データ構造に重複を許したくない場合はこのSetインターフェースを利用する。
このクラスにはHashSetというものがあるため、それを利用する。

Map
データをキーと値のペアで管理する場合は、Mapインターフェースをの実装クラスをを使用する。
これはHashMapを利用する。キーは一意である必要があるが、値は重複してもいい


HashSetではなくTreeSetを使用すれば文字列は辞書順、数値は昇順に従って行われる

ラムダ式
ラムだ式はクラスをシンプルに定義できるようにしたもの
