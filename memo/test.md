クラス継承に置ける基礎的な知識について

継承したクラスはその要素をもっているため、変数などもサブクラスから参照することが可能。

継承の際、デフォルトクラスはpublicとして扱われる。そしてデフォルトフィールドの場合は同じパッケージからアクセスすることが可能。
注意点としてサブクラスであっても[コンストラクタは引き継がない]ということ

引数が一つだけの時()は省略できる
[関数インターフェースの型 変数名 = 引数 -> {処理};]

処理が一つだけの時は{}も省略できる。しかし、2つあるときはコンパイルエラーになるので注意

returnの文字も省略できる。
ここで注意！！

ラムダ式の処理が一つしかなくて何かしらの戻り値を戻すときは、returnの文字を省略できるのではく[記載できない]ので注意する
{}でくくった場合はreturnを記載しないとコンパイルエラーになる

3:ラムダ式のメソッド変数
ラムダ式を使用しているメソッド内でローカル変数を定義している場合、
ラムダ式の引数と同じにしてしまうとコンパイルエラーが起きる。
ラムダ式の引数では
[関数インターフェースの型 変数名 = (String name) -> {処理};]
上記のようにこの中で定義しているため、同じ変数が存在することとなりコンパイルエラーになる。

4:ラムダ式におけるローカル変数
メソッド内に定義されている変数をラムダ式内で使用する際は
[final]または[実質的なfinal]出ないとだめ。
実質的なfinalとは何でしょう？

int cut = 0;
Runnable r () ->{
System.out.plint(cut)
}
これは大丈夫。
cutの値が[変化していない]から。

これがfor文などで変化するようにしてしまったり、
int cut = 0;
Runnable r () ->{
System.out.plint(cut)
}
cut = 20;

なんてことにするとcutの値が変化した扱いになってしまうのでコンパイルエラーになる。

ここで大事なのは実質的なfinalの概念を抑えよう

関数インターフェースの種類
Javaにはよくつかわれる関数インターフェースは常に定義されている
[Function],[Runtime],[Predicate]、[Supplier]、[Consumer]
これらその種類になる。
関数型インターフェースの特徴

関数インターフェース  メソッド   説明       
Function<T,R>  R apply(T) 　引数を受け取って指定された型(R)で返す
Predicate<T>  boolean test(T) 引数を受け取って評価する
Supplier<>   T get()　なにも受け取らずに結果だけを返す
Consumer<T> void accept(T) 引数を受け取ってなにも返さない。処理のみを行う

Comparator
カスタム順序を適応することができる。大商比較を前提にしており、equals()を使えるものを渡す。

こちらを関数インターフェースとして使用した場合は[compare()]をOverrideを実装する必要がある。
ラムダ式を使用しているのであれば、[implements Compare<T>]こちらは省略されている可能性があるからそこは注意する。
これができる理由はComparatorが関数式インターフェースだから

Comparableを使う場合はcompare()ではなく[compareTo()]を使用する。

compareTo()を使用すると自然な順番になるためintだったら昇順みたいになる。
